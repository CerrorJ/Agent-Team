# 模型后端故障恢复

Claude / Codex 是执行引擎，同一引擎可以连接不同厂家。错误处理按实际错误和后端配置决定，不再将 Claude 的 `session limit · resets` 文案当作所有厂家的统一协议。

## 错误类别

| 类型 | 默认处理 |
| --- | --- |
| `rate_limit` 短时限流 | 未执行工具或产生结果时，最多自动重试两次；失败后默认冷却 60 秒 |
| `quota_exhausted` 额度耗尽 | 不自动重跑任务；未提供恢复时间时，默认冷却 5 分钟后允许重新尝试 |
| `billing` 余额或计费问题 | 不自动重跑；提示处理账号，默认冷却 60 秒 |
| `authentication` 认证失败 | 不自动重跑；提示处理凭证，默认冷却 60 秒 |
| `configuration` 模型或权限问题 | 不自动重跑；默认只限制对应账号和模型，冷却 60 秒 |
| `service_unavailable` 服务暂不可用 | 工作开始前有限重试；失败后默认冷却 30 秒 |
| `unknown` 未识别错误 | 保留原始错误，不自动重试、不记录后端冷却 |

冷却结束只表示允许重新尝试，不保证服务商额度已经恢复。配置/余额/认证问题仍需要处理对应账号。所有冷却均为进程内状态，重启清除。

优先使用 CLI 实际暴露的结构化 `code`、`status`、`retry_after_ms`、`retry_after`、`Retry-After` 和 `reset_at` 字段；CLI 隐藏的 HTTP 信息不会被虚构补全。拿不到结构化信息时，再匹配中英文文本。额度或余额错误优先于通用 429 判断，避免把额度耗尽误当成可立即重试的限流。

`retry_after` / `Retry-After` 数值按秒，`retry_after_ms` 按毫秒；`Retry-After` 也支持 HTTP 日期。`reset_at` 支持 Unix 秒、毫秒或完整日期字符串。文本支持 `retry in 2 seconds`、`30秒后重试` 和旧版 Claude 的带时区时钟格式；无法解析时使用该错误类别的冷却配置，不再默认封禁 5 小时。

## 扩展厂家规则

默认读取 `config/provider-errors.json`，可通过 `PROVIDER_ERROR_CONFIG` 指定其他路径。修改后重启生效，规则和正则在加载时校验。

以下为自定义规则的示意，错误码需要替换为实际服务商返回值：

```json
{
  "maxRetries": 2,
  "baseDelayMs": 1000,
  "maxRetryDelayMs": 30000,
  "rateLimitCooldownMs": 60000,
  "quotaCooldownMs": 300000,
  "configurationCooldownMs": 60000,
  "serviceCooldownMs": 30000,
  "rules": [
    {
      "endpointPattern": "vendor\\.example",
      "codePattern": "^VENDOR_QUOTA_EMPTY$",
      "type": "quota_exhausted",
      "scope": "account",
      "cooldownMs": 600000
    },
    {
      "endpointPattern": "vendor\\.example",
      "messagePattern": "该模型并发已满",
      "type": "rate_limit",
      "scope": "model"
    }
  ]
}
```

自定义规则优先于内置识别，按数组顺序取第一条匹配规则。同一规则指定的条件必须全部满足，至少设置文案、错误码或 HTTP 状态中的一个条件。`type: unknown` 可用于排除某类误判。服务端提供的有效重试时间优先于本地冷却配置；超过 `maxRetryDelayMs` 时不截短服务端时间强行重试，而是记录冷却并交给现有失败/团队交接流程。

## 后端范围与团队代班

冷却按实际端点和凭证的哈希标识记录，不输出凭证。同一后端账号的多个 Bot 共享账号级冷却；模型级故障只影响对应模型。备用候选会排除仍处于冷却中的共享后端，避免只换 Bot 却继续使用同一受限账号。运行中更换端点、凭证或模型会实时按新配置查询可用性。

没有显式凭证的 Bot，按引擎的本机登录归为同一个账号。CLI 内部 profile、代理网关背后的共享额度无法仅凭环境变量可靠推断；这种情况可以在 Bot 的 `cliEnv` 映射中加入 `AGENT_TEAM_QUOTA_GROUP`，将值映射到 `.env` 中相同的额度组名称，显式合并不同端点或引擎的账号级冷却。

自动重试共享同一执行超时预算，等待支持取消。一旦观察到工具调用或结果输出，就不再自动重跑整轮任务，避免重复写文件、发消息或执行命令。失败中已获取的 CLI 会话 ID 会随错误保留，主消息流程会持久化该 ID。所有通过 `runCli` 的执行入口复用这套策略；原生 `/compact` 有独立协议，目前仅在主消息失败处理里复用错误分类，不自动重试。

验证：`pnpm test`、`pnpm build`、`pnpm lint`、`pnpm format:check`。
