# 启动回调取消竞争修复

2026-10-23，内核0.5.9兼容增量；协议1、schema7不变。独立飞书入口和嵌入式入口继续使用同一CLI Runner。

## 缺陷与修复

`onProcessStart`在注册AbortSignal监听前执行。内核写入执行片段PID失败时，该回调会同步取消；AbortSignal不会在随后添加监听时重放先前事件。原实现可能漏掉整树终止请求，并在根进程自然退出后按取消处理。

现在注册监听后立即检查`signal.aborted`，仍通过唯一、缓存的终止Promise等待原终止端口。不改变权限、执行参数、任务状态机或停止证据要求；端口失败继续返回STATE_UNCERTAIN。

新增真实子进程回归在开始回调内同步取消、记录终止端口调用。修复前调用0次而断言失败；修复后恰好1次。夹具自然结束有界，回归失败也不遗留无限进程；已有真实父子进程终止及终止失败/根进程自然退出仍未知的回归继续通过。

验证：`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`、`pnpm build:kernel`；专项为`pnpm exec tsx --test tests/process-abort-race.test.ts tests/process-stop.test.ts`。版本、构建摘要与桌面关联提交在产物锁文件记录，正式消费前必须从干净已提交源码重建。
