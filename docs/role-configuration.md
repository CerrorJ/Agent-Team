# 角色六步配置的内核增量

基于开发提交`1938441637e673744f0b95a60bcffc08f8509958`继续实现。内核0.6.0、协议1、数据schema8，新增`role-configuration`能力。2026-10-24完成本增量独立测试及审查，桌面尚未消费；纬舟`6d3d288`继续锁定0.5.9。后续提交后从干净源码重建、核对摘要，再单独更新桌面锁定及客户端。

## 角色字段与不变量

- `slug`为工作空间内唯一稳定标识，使用小写字母、数字与单连字符，最多64字符。保存后只可重命名展示名称，不能更改标识；历史标识仍占用，防止旧引用被另一角色认领。
- `inputRequirements`和`deliveryRequirements`保存输入、交付要求，执行时读取本次Run的角色快照。它们是任务说明，不扩大CLI工具或目录权限。
- `maxConcurrency`范围1—2；本机总槽位仍为2，每项目仍只有一位写者。角色新版本调高上限时，仍活动的旧Run固定的较小上限继续有效。旧Run缺省为1。
- 所有配置变更新增版本并重置试运行/启用状态。旧客户端省略新增字段时，继承最新配置，不擦除标识、要求或并发值。新建旧客户端角色获得基于UUID的稳定默认标识。
- 已有v7角色/Run缺少新增字段时，读取不填充或回写历史JSON。第一次编辑只在新版本记录默认配置。

保存、标识唯一性、版本比较交换、事件、通知意图及幂等回执均在同一SQLite事务中；没有把角色规则放到桌面或渠道层。

## 数据与备份兼容

schema8用于阻止旧内核严格解析不认识的新角色字段。升级v7前保存一致SQLite备份，升级只改变版本标记，不重写旧角色JSON。v7便携备份仍可只读预览、恢复到新目录，再由新内核迁移；原备份不变。较新或不支持的schema继续拒绝。

备份检查仍先核对文件清单、摘要及完整SQLite schema。新增便携数据库头检查，拒绝WAL主库伪装的快照，避免仅预览就创建原目录的wal/shm文件。实际VACUUM INTO快照沿用独立日志格式；格式依据见[SQLite官方文件格式](https://www.sqlite.org/fileformat.html#vnums)。此限制不改变活动工作台的WAL模式，不放宽触发器、视图、虚拟表或约束校验。
